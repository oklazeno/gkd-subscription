## 这个项目在做什么

**先说清楚：本项目不是规则原创项目。**

规则是上游作者写的。感谢以下四位规则维护者提供的优秀开源规则：

| 维护者 | 在本整合版中的角色 |
|---|---|
| Lin-arm | 合并骨架 |
| 甘霖 | 并入其独有规则 |
| 梦念逍遥 | 并入其独有规则 |
| 奥怪 | 并入其独有规则 |

他们负责**规则编写、规则维护、场景适配**，全部规则的著作权归他们所有。

本仓库负责的是「整理」这一层：多源整理、规则合并、重复规则处理、默认配置优化、部分场景补充。

希望通过整理，让更多普通用户能更简单地使用 GKD。**四个源各自都是完整可用的订阅，推荐你也去看看它们。**

## 为什么需要这个项目

GKD 本身只是一个自动化执行工具，不包含任何广告规则。想用得舒服，通常得自己：

1. 寻找多个规则订阅源
2. 判断哪些规则值得开启
3. 处理多个订阅之间的重复
4. 遇到误触后自行排查

对普通用户来说，最大的问题不是没有规则，而是——**选择和维护规则本身就是成本。**

本项目的目标不是「规则更多」，而是让这个成本低一点。

## 具体做了哪些事

- **多源合并**：四个源按「应用包名 + 规则组名」整理合并。四源合计 1944 个应用、4978 个规则组，整理后 1036 个应用、3337 组。同一个应用的同一条规则只保留一份，降低重复触发概率
- **默认配置优化**：从上游默认关闭的规则里，按场景安全度、选择器精度、快照佐证分层，挑出一批适合普通用户的广告类规则**在文件里标记为开启**（已排除金融/支付/政务类，以及含「还款、转账、支付、确认、提交、申请」等业务动作词的规则）
  - ⚠️ **口径说明（2026-09-20 更正）**：GKD 的「规则分类」开关优先级**高于**单组开关。本订阅 11 个分类里只有「开屏广告」默认开，其余 10 个默认关 —— 所以上面那批规则**需要你在 GKD 里打开对应分类后才会真正生效**（打开分类 = 该类全部规则整批开启，包括上游刻意保守关掉的组）。**默认状态下实际生效的是：229 组「开屏广告」+ 3 条全局规则（开屏广告-全局 / 更新提示-全局 / 青少年模式-全局）。**
- **场景补充**：补了一批银行类 App 的规则，这类 App 上游覆盖较少

**关于耗电**：GKD 官方文档说明，耗电只和「启用的规则」以及「当前界面的节点数量」有关，与订阅文件大小无关。同时装多份互相 fork 的订阅，等于重复开启同一批规则——这也是建议只用一份的原因。

## 使用建议

1. 建议只装一份订阅，不要和其他订阅同时开
2. 银行、支付类 App 优先只开「开屏广告」，其余规则按实际情况开
3. 拿不准的规则先只开一组，观察一两天再加
4. 涉及资金、隐私、重要业务的页面，不要完全依赖自动点击

## 一、GKD 是什么

GKD 是一款 Android 开源应用，基于系统「无障碍服务」实现自动点击屏幕。最常见的用途是**自动跳过 App 开屏广告、关闭各种弹窗**。

- **项目主页（官方）**：https://github.com/gkd-kit/gkd
- **官方网站与文档**：https://gkd.li
- **开源协议**：GPL-3.0

GKD **本身不内置任何规则**，它只是一个执行引擎。你需要导入「订阅规则」它才会工作。本仓库提供的就是一个订阅规则。

## 二、小白上手：四步搞定

### 第 1 步：下载安装 GKD

**方式一：官方 Release 页面（推荐）**

打开 https://github.com/gkd-kit/gkd/releases/latest

下载最新的 `gkd-v1.12.1.apk`（约 3.14 MB）。

> 如果 GitHub 打不开，用下面方式二。

**方式二：官网直链**

打开 https://gkd.li/guide/ ，点击页面上的「正式版 v1.12.1.apk」下载。

> 提示：某些手机自带浏览器会拦截下载，建议换 Via 浏览器（https://viayoo.com）或 Chrome。

**方式三：Google Play**

https://play.google.com/store/apps/details?id=li.songe.gkd

> 注意：Play 版与 GitHub 版功能有差别，详见官方 FAQ。

### 第 2 步：授权无障碍权限

1. 安装后打开 GKD
2. 首页会提示「无障碍权限」，点右侧「授权」
3. 在系统设置里找到 GKD，打开开关
4. 返回 GKD，确认权限状态正常

> 这一步是必须的。GKD 靠无障碍服务读取屏幕内容并点击，不开权限它无法工作。

### 第 3 步：导入本订阅

1. 打开 GKD，进首页 →「订阅」
2. 点右下角 `+` 号
3. 粘贴这一行：

   ```
   https://cdn.jsdelivr.net/gh/oklazeno/gkd-subscription@main/gkd.json5
   ```

   > 这一步如果一直转圈或报错，改用 GitHub 原始地址：
   > ```
   > https://github.com/oklazeno/gkd-subscription/raw/main/gkd.json5
   > ```

4. 点确定，等待状态变成「已启用」，右侧开关变蓝

### 第 4 步：启用规则

订阅导入后，进入「订阅 → 应用规则」，你会看到手机里已安装的应用列表。**默认只有「开屏广告」类规则是开启的**，其他类别（弹窗、信息流等）需要你按需手动打开。

> 建议先只开「开屏广告」，用几天没不适再逐步开启其他类别。开太多可能误点。

完成。之后打开有开屏广告的 App，GKD 会自动帮你跳过。

## 六、常见问题

**Q：订阅导入失败 / 一直转圈？**
1. 先用电脑浏览器打开订阅链接，能显示一大段 JSON 内容说明链接正常
2. 本仓库提供两个链接（GitHub 原始地址 + jsDelivr 镜像），**换另一个再试**——两者内容完全相同
3. 都打不开，多半是网络环境问题（国内访问 GitHub 原始地址经常不稳定），可挂代理后再试，或用镜像链接
4. 检查手机网络

**Q：规则不生效，广告还在？**
1. 确认 GKD 的**无障碍权限**没被系统关掉（国产系统容易自动清理）
2. 确认订阅状态是「已启用」且开关是蓝色
3. 进订阅 → 应用规则，找到对应 App，确认该类规则已开启
4. 规则可能过期了——App 改版会导致规则失效，等订阅更新或自行反馈

**Q：GKD 老是被系统杀掉？**
1. 手机设置 → 应用管理 → GKD → 耗电管理 → 设为「无限制」
2. 在多任务界面把 GKD 卡片锁定，防止一键清理杀掉

**Q：能不能同时导入多个订阅？**
不建议。同一个应用被多个订阅覆盖时，规则会叠加触发，导致重复点击、误触、卡顿。**用一份就够了**——本整合版或者上游任一份都行。

**Q：这和上游的订阅比，我该选哪个？**
都行。上游四家各自都很完整，选它们没问题。本整合版的差别只在「省事」：不用自己判断装哪几份、不用逐个配默认开关。你要是愿意自己折腾，用上游反而更可控。

**Q：显示「匹配应用数」很少，是不是坏了？**
不是。它只统计你**手机上已安装**的应用数量。规则库里没装的应用不占运行时资源。

**Q：费电吗？**
GKD 本身很轻量。但如果发现异常耗电，通常是无障碍服务阻止了系统深度休眠，可以减少开启的规则类别。

**Q：会误点掉我要用的东西吗？万一误触了怎么办？**

有可能。这是所有自动化点击工具的固有风险，不回避。真发生了，按这三步走：

**第 1 步：先关掉那一组规则（10 秒搞定）**

    GKD → 订阅 → 点本订阅 → 应用规则 → 找到那个 App → 把对应规则组的开关点成灰色

想不起来是哪一组？就先把**这个 App 的规则全部关掉**，再一组一组开回来试——比逐条猜快。

**第 2 步：反馈给我修（可选，但很值）**

用 GKD 里的「用户反馈」按钮，或到本仓库提 issue。按下面「怎么反馈」的三行模板写，我会去定位并修掉那条规则。

**第 3 步：急用就先全停**

GKD 主界面把**总开关**关掉，所有规则立即失效，不会再自动点任何东西。等修好再打开。

平时的预防建议：

    1. 银行 / 支付类 App 只开「开屏广告」类，其余按需
    2. 拿不准的规则先只开一组，观察一两天再加
    3. 涉及资金、隐私、重要操作的页面，不要完全依赖自动点击

**Q：广告没被跳过、规则失效了，怎么反馈？**

最方便的方式是用 App 内的「用户反馈」按钮，它会直接打开本仓库的反馈页：

    GKD → 订阅 → 点本订阅 → 用户反馈

反馈不用写很长，三行就够，我会去定位规则：

    App 名称（或包名）：
    出问题的页面（例：打开 App 后 3 秒出现的全屏弹窗）：
    期望动作（例：应该点右上角的跳过 / 应该关掉这个弹窗）：

**能附快照最好。** GKD 的「生成快照」会记录当时的页面结构和截图，有它我就能直接验证选择器为什么没命中，修起来快很多。没有快照也能提，只是可能要来回问几句。

如果你自己也写规则，欢迎直接把修复提交到**原始规则源**（见第四节）——那是对上游生态最直接的帮助，本订阅下次融合时会自动带上。

### 关于两个链接的区别

| 链接 | 说明 |
|---|---|
| `cdn.jsdelivr.net/gh/…` | 全球免费 CDN 镜像，无需任何额外配置。**国内多数网络可直连、下载快**；缺点是**有缓存**，更新后可能要等几小时才同步 |
| `github.com/…/raw/…` | GitHub 官方原始地址。**内容始终最新**（无缓存），但国内部分网络环境访问不稳定 |

两个链接指向同一份订阅，**选一个能用的即可**。判断标准很简单：在手机浏览器里能打开并显示 JSON 内容，就可以填进 GKD。

> 长期维护，**随缘更新**（不承诺固定周期）。订阅内的「检查更新」会读取版本检测文件，有新版即可一键更新，**不需要删掉订阅重新添加**。

### 关于更新频率（请先看这里）

本订阅采用「随缘更新」，不设固定周期。理由很实在：上游规则的变更本身不紧急，而每次更新都要走一遍「拉上游 → 融合去重 → 重放配置 → 语法校验 → 回归验证」的流程——**草率发布比不发布风险更大**。

会在这些情况下推新版：

    1. 上游有较大范围的 App 覆盖更新时
    2. 收到明确的「误触」或「规则失效」反馈时（这类会优先处理）
    3. 我自己实机用了一段时间、确认稳定之后

所以：**装一次够用很久**，你不需要天天盯着版本号。

反过来说，某天你发现某个 App 的广告关不掉了，大概率不是订阅坏了，而是**那个 App 改版导致规则失效**——按上面的方式反馈一条，我会优先修。

给你的建议：**每 1~2 个月点一次「检查更新」就够**，不必频繁操作。
